# CPU戦術カタログ（検討用）

2026-10-11 作成。戦術の候補を漏れなく検討するための台帳であり、採用・強さ・優先順位を決めた文書ではない。採用ルールは現行の [`quota_rule_v1.21.md`](../quota_rule_v1.21.md) に従う。既存CPUの仕様は [`cpu_strategy_v1.0.md`](../cpu_strategy_v1.0.md)、実装は `quota/characters.py`・`quota/ai.py` と Unity 側の対応コードを参照する。得点ルールの変更案（「五種の品揃え」や達成ボーナス）は未採用として扱う。

## 用語と前提

- **戦術**：ある局面で合法手の候補を作り、観測・推定に基づいて選ぶ具体的な方法。下記の各項目は単独の「人格」ではなく、組み合わせられる部品とする。
- **戦略**：得点・達成確率・時間・妨害・称号などの優先度、戦術の使い分け、切替条件を決める方針。戦術間の優先順位は本書では決めない。
- **確定情報**：場札、各人のノルマ・収集・実績、捨て札、山札枚数、膠着状態、特殊行動の使用状況、公開された手番履歴。**未知情報**：山札の順序・内訳、伏せられた除外札8枚の内訳、相手の将来の行動。CPUがエンジン内部の `deck` や `removed` の実体を参照する戦術は不可とする。
- 各ラウンドは108枚（4種類×1〜13×各2枚、金貨4枚）を新しく混ぜ、8枚を伏せて除外する。場札は3人なら7枚、4人なら6枚。ラウンドが変わると記憶と確率分布を初期化する。累計得点・達成回数・特殊行動の新ラウンドでの回復は別に扱う。
- **配り直しで場から消えた札は消滅しない。** 膠着時・特殊行動時とも、残った場札を山札へ戻して混ぜる。放棄された札は捨て札に移り、実績とともにそのラウンド中は山札へ戻らない。配り直し履歴は「再出現し得る既知の札」の記憶であり、捨て札の記憶とは異なる。
- 手番開始時に場札を補充する。ノルマ1は取った瞬間に1点を得て手番終了。ノルマ2以上を取った手番には通常収集できない。状態Bは同種または金貨を残り必要数以内で複数枚取れ、選んだ順序が実績の並び順になる。放棄後は同じ手番に新しいノルマ選択またはパスができる。
- 達成点はノルマ数に、7〜9枚なら＋1、10〜12枚なら＋3、13枚なら＋6。ラウンド末の並び順ボーナスは同番号＋2、差1なら＋1、連続金貨は2枚目＋1・3枚目＋2・4枚目＋3。称号は単色達成＋15、生粋の買い付け＋5、五種の品揃え＋5。最後の称号には達成回数の下限がない。
- 配り直し＆取得、ダブルアクションはそれぞれ1ラウンド1回。どちらも手番開始時、行動前に宣言し、同じ手番で併用できない。パスは取れる札があっても合法。獲得のない手番が人数分続くと膠着し、初回は配り直し、配り直し後も獲得なしが続けばラウンドが終わる。

## 1. 観測・記憶・推定

以下は行動を直接決める前の戦術部品。`既存` は現行CPUに近い処理があるもの、`拡張` は今後の候補。既存実装が同じ精度・情報制限を満たすという意味ではない。

| ID | 状態 | 戦術・観測対象 |
|---|---|---|
| O01 | 拡張 | **公開札の帳簿**：商品は種類×数字ごと、金貨は合計で、現在の場・各人のノルマ/収集/実績・捨て札を数える。二重計上を避け、山札にないと確定した札を特定する。 |
| O02 | 既存→拡張 | **残存種類数**：同種または金貨の入手可能数を見積もる。現在の実装の種類合計だけでなく、数字別の残量と配り直し履歴を使えるようにする。 |
| O03 | 拡張 | **出現履歴**：場に現れた種類・数字・時点・その後の移動先を記憶する。前のラウンドの履歴は持ち越さない。 |
| O04 | 拡張 | **配り直し時の戻り札**：配り直し直前に場に残った札は山札へ戻ったと記録する。新しい場に出なかったものも再出現候補に残す。同種同番号の物理的な2枚は見分けられないため、同一個体と決めつけない。 |
| O05 | 拡張 | **除外札を含む事後分布**：残量から次の補充で特定種類・数字が出る確率を更新する。除外8枚を「実はすべて欲しい札」とも「すべて安全」とも仮定しない。 |
| O06 | 拡張 | **複数枚の出現見込み**：次の補充1枚だけでなく、自分の次手番までに補充される枚数、必要枚数がそろう確率、手番前に相手が取る確率を別々に推定する。 |
| O07 | 拡張 | **見えない札の下限・上限**：ある商品・金貨が山札に残る可能性の幅を出す。既知の実績・捨て札が多い終盤は「達成不可能」を早く確定できる。 |
| O08 | 拡張 | **相手の不足枚数**：公開ノルマと収集から、相手ごとに必要な種類・残り必要数・現在の場で取れる枚数を保持する。 |
| O09 | 拡張 | **相手の行動傾向**：公開手番でのノルマ選択、パス、放棄、金貨使用、特殊行動を記録し、次にどの札を取るかの予測に使う。断定せず不確実性を残す。 |
| O10 | 拡張 | **残り手番・ラウンド終了危険度**：山札枚数、場の欠け、手番順、膠着カウンタから、自分にあと何回行動が回り得るかを推定する。 |
| O11 | 拡張 | **相手の称号狙いの推測**：各相手について単色達成・生粋の買い付け・五種の品揃えの成立可能性と、実際にそれを優先していそうな確率を別々に持つ。公開された実績・ノルマ・金貨使用に加え、同種札への固執、金貨を使える場面での見送り、不足種類の選択などの行動履歴を手掛かりにする。合法手や場札の制約で他を選べなかった場合は意図の証拠にしない。相手の内面や非公開情報を読んだと決めつけず、称号の見込みと推測の不確実性を更新する。 |

### 確率計算の境界

場にある札は「これから出る札」として数えない。実績・捨て札・手元にある札も山札にはない。初回配札後、配り直しが一度もなければ、山札と伏せられた除外札を合わせた未知の母集団について、同種同番号の未判明残数を使える。未知の母集団が `U` 枚、そのうち目的の種類が `u` 枚なら、無作為な次の1枚が目的の種類である周辺確率は `u/U`。次の `k` 枚に少なくとも1枚含まれる確率は `1 - C(U-u, k)/C(U, k)`（`k <= U`、相手に取られないなどの条件付き）。たとえば3人戦の初回配札7枚に特定の商品・数字が1枚もなければ、その種類・数字の次の1枚の確率は `2/101`。伏せられた8枚にその2枚が入っている可能性も含む。**108枚から8枚を引いた100枚の山札すべての内訳が既知、とは扱わない。**

配り直し後は、以前見えた札が山札へ戻り、未知札・伏せられた除外札と区別して推定する必要がある。たとえば山札 `D` 枚のうち、山札へ戻ったと確定している既知札が `R` 枚、その中の目的札が `r` 枚、残る未知の候補群（未知の山札分と除外札を合わせたもの）が `U` 枚で目的札が `u` 枚なら、十分に混ざった山札の次の1枚の周辺確率は概念上 `〔r + (D-R)×u/U〕/D`。再出現した同種同番号札の物理的同一性まで分からない場合は、各可能な割当てに重みを置いた事後分布、または公開履歴に整合する山札・除外札のサンプルで近似する。後者の計算能力自体は使ってよいが、非公開データへの直接アクセスはしない。

## 2. ノルマ札の選択（状態A、放棄直後）

| ID | 状態 | 戦術 |
|---|---|---|
| Q01 | 既存 | **即時の1点**：ノルマ1をその場で確定する。1点と1回の達成に加え、並び順や称号の変化を考慮する余地がある。 |
| Q02 | 既存 | **中くらいのノルマ**：3〜6など達成しやすさを重視して選ぶ。数字の閾値は戦略側の調整対象。 |
| Q03 | 既存 | **大きなノルマ**：7〜13の達成ボーナスを含む高得点を狙う。完成できるかを別途評価する。 |
| Q04 | 既存→拡張 | **現場即応**：ノルマ札を取った後、既に場にある同種・金貨の枚数と数字別の並び順を見て選ぶ。今取れる札は次の自手番まで場に残る保証がない。 |
| Q05 | 既存→拡張 | **山札見込み**：残存同種・金貨数、残り補充機会、除外8枚の不確実性から、候補ごとの達成見込みを比べる。 |
| Q06 | 拡張 | **競合回避**：同じ種類のノルマを持つ相手、先に手番が来る相手、相手の不足枚数から、自分が取れる見込みを調整する。 |
| Q07 | 拡張 | **必要手番数**：同じ期待得点でも、完成までの自分の手番が少ないノルマを区別する。残りラウンド時間と組み合わせる。 |
| Q08 | 拡張 | **未達成損失**：完成できなかった場合、ノルマ札・収集札が無得点となる危険を候補別に見積もる。 |
| Q09 | 拡張 | **達成ボーナス境界**：6→7、9→10、12→13の得点段差を織り込む。境界だけを見て完成確率を無視しない。 |
| Q10 | 拡張 | **次の束へのつなぎ**：既存の実績末尾と候補の数字の関係で、束の境界に生まれる並び順ボーナスを比較する。 |
| Q11 | 既存→拡張 | **単色継続**：現在までの全達成ノルマが同じ種類で、3回以上の成立が見込めるとき、その種類の候補を検討する。別種類を達成するとそのラウンドの単色称号は失われる。 |
| Q12 | 拡張 | **五種の不足種類**：実績に欠けた種類を埋める候補を見る。金貨はノルマ札にできないため、金貨の入手は収集の局面に依存する。 |
| Q13 | 拡張 | **達成回数と同点判定**：小ノルマを複数回完成する場合の達成回数と最終同点時の効果を区別する。得点に勝る優先条件とはしない。 |
| Q14 | 拡張 | **先取りと保留**：高価値のノルマ札を今確保する利益と、ノルマなしで次手番に別候補を待つ損得を比べる。パスによる膠着も加味する。 |

## 3. 収集枚数・カード・順序（状態B）

| ID | 状態 | 戦術 |
|---|---|---|
| C01 | 既存 | **完成優先**：現在取れる同種・金貨から、必要数を満たせるなら完成させる。 |
| C02 | 拡張 | **あえて一部を残す**：取れる札をすべて取らず、後で自分が使う/相手に渡さない効果、並び順を整える効果を検討する。残すと相手に取られる危険もある。 |
| C03 | 拡張 | **金貨の節約**：同種札で必要数を満たせるなら金貨を残し、将来の難しいノルマや別称号への選択肢を保持する。 |
| C04 | 拡張 | **金貨の即時使用**：完成、ラウンド終了回避、相手の金貨取得阻止が重要な局面では金貨を使う。節約とは両立しない候補として比較する。 |
| C05 | 既存→拡張 | **同番号を隣接**：複数枚取得の順を選び、同番号の隣接による＋2を増やす。商品種類は問わないが、収集時は自分のノルマと同種か金貨だけが合法。 |
| C06 | 既存→拡張 | **連番をつなぐ**：末尾から差1の数字をつなぐ。13と1は連番にならない。 |
| C07 | 拡張 | **束の先頭・末尾を整える**：現在の実績末尾→ノルマ札、今回の束末尾→次のノルマ札という境界を見据えて取得順を選ぶ。取得済みの並び順は変えられない。 |
| C08 | 拡張 | **金貨の連続配置**：金貨が複数枚あるとき連続させ、2枚目以降の増分を得る。商品札を間に入れると連続が切れる。 |
| C09 | 拡張 | **金貨の挿入位置**：商品札との境界が0点になることと、金貨連続の得点を併せて、金貨を置く順番を選ぶ。 |
| C10 | 拡張 | **今の得点と次の接続余地**：同じ現在の並び順ボーナスを得る順序でも、末尾の数字・金貨の連続長が異なれば、将来の接続見込みが変わる。 |
| C11 | 拡張 | **同時取得順の探索**：場に取れる札が複数あるとき、部分集合と順列を区別する。数字・種類が同一の札の入れ替えだけは同一視できる。 |

## 4. 放棄・パス・特殊行動

| ID | 状態 | 戦術 |
|---|---|---|
| A01 | 既存→拡張 | **達成不能の放棄**：公開札と除外札の不確実性を考慮し、完成可能性がなくなったノルマを捨てる。条件は将来の配り直しで戻る札を含めて計算する。 |
| A02 | 既存→拡張 | **見込み比較による放棄**：継続の見込みと、同じ手番で場の別札をノルマにする見込みを比べる。既に集めた札の損失も計算に入れる。 |
| A03 | 拡張 | **ラウンド終了前の放棄**：未達成のまま終わる見込みが高いとき、小さな別ノルマを完成させられるかを考えて乗り換える。放棄は同じ手番で新しいノルマ選択まで可能。 |
| A04 | 拡張 | **競合からの撤退**：同じ種類を狙う相手が先に大量に取れるなら、完成見込みの変化に応じて放棄・継続を比べる。 |
| A05 | 拡張 | **称号維持のパス**：別種類のノルマ札しか場にないとき、単色称号を壊して取るか、パスして待つかを比較する。獲得なしによる膠着を無視しない。 |
| A06 | 拡張 | **場を固定するパス**：今ある札を取らず、次の相手に同じ場を渡す。獲得のない手番には補充がないので、相手に有利な札を残す危険を含めて判断する。膠着時の配り直しは別に予測する。 |
| A07 | 既存→拡張 | **配り直し＆取得**：場に自分の望む札がないとき使う。現在の場札は山札に戻り、自分が新しい場で最初に1アクションできる。相手に有利な場を作る可能性もある。 |
| A08 | 拡張 | **配り直しによる相手の妨害**：相手が次手番に必要札を取れそうな場を入れ替える。場の札は戻るので、その種類を恒久的に減らす効果はない。 |
| A09 | 拡張 | **配り直し使用時期**：残り山札、膠着の状態、相手の順番を見て、1回限りの権利を今使うか後に残すかを比べる。 |
| A10 | 既存→拡張 | **ダブルで完成**：1回目に収集・達成し、補充後の2回目に新ノルマを確保するなど、状態遷移を含む2行動を考える。 |
| A11 | 拡張 | **ダブルで先取り**：相手に回る前に2回目の収集または新ノルマ選択を行う。1回目の後に山札から場が補充される点を考慮する。 |
| A12 | 拡張 | **ダブルの終盤境界**：1回目で札を取りすぎると補充中に山札が尽き、2回目は実行されない。山札枚数と場の欠けを確認する。 |
| A13 | 拡張 | **特殊行動の温存**：1ラウンド各1回の権利を残す判断。次ラウンドでは回復するので最終手番での温存価値はない。 |
| A14 | 拡張 | **膠着を進めるパス**：公開カウンタを見て、場の配り直しやラウンド終了が自分の点差・未達成札にどう作用するかを比較する。獲得があるとカウンタとフラグはリセットされる。 |
| A15 | 拡張 | **終盤の難局に備える温存**：ラウンド前半で配り直し・ダブルを使う利益と、目標や残り札が明らかになる後半まで保持する選択価値を比較する。終盤に特定の同種札が不足する、相手に先取りされるなどの難局で使えることを想定する。同時に、使わないままラウンドが終わる可能性も見積もる。A13の温存判断を終盤の救済用途まで具体化した候補。 |

## 5. 称号・複数目的

| ID | 状態 | 戦術 |
|---|---|---|
| T01 | 既存→拡張 | **単色の成立可能性**：達成ノルマの種類がまだ1種類に限られ、3回目に届く見込みがあるか追う。異種の「収集札」は単色判定を壊さない（そもそも通常は同種か金貨のみ取得可能）。 |
| T02 | 拡張 | **単色の例外判断**：異種の確実な得点を取れば単色称号が消える局面で、その確定点と称号の残存見込みを比べる。 |
| T03 | 既存→拡張 | **生粋の維持**：各達成束に金貨を使わず3回以上を狙う。未達成の束で金貨を持っていても、その束が実績に移るまでは成立条件は確定しない。 |
| T04 | 拡張 | **生粋の例外判断**：金貨を使って現在のノルマを完成する価値と、＋5の称号が失われる価値を比較する。 |
| T05 | 拡張 | **五種の不足商品**：実績にない種類を数え、自然に取れるノルマ・収集候補の寄与を評価する。 |
| T06 | 拡張 | **五種の金貨条件**：金貨を少なくとも1枚、完成する束で実績に入れられるかを確認する。金貨はノルマ札にできない。 |
| T07 | 拡張 | **称号の両立・排他**：単色＋生粋は両立可能。五種は4種類の商品を実績に入れる必要があるが、収集できるのはノルマと同種か金貨だけなので、異なる種類のノルマ達成が必要。従って現行ルールでは単色と五種は両立しない。五種と生粋も、金貨を実績に入れると生粋が失われるため両立しない。称号の同時達成を誤って見積もらない。 |
| T08 | 拡張 | **確定した称号を追いすぎない**：五種など既にそのラウンドで成立した称号に、さらに札を重ねても同称号は追加されない。 |
| T09 | 拡張 | **達成回数の確保**：単色・生粋の3回条件と最終同点時の達成回数を別々に追う。 |

## 6. 相手への干渉・競争

| ID | 状態 | 戦術 |
|---|---|---|
| P01 | 既存→拡張 | **相手の必要札を取る**：相手が待つ種類・金貨を、合法的に自分のノルマ/収集に使えるなら先に取る。自分の機会費用を別に数える。 |
| P02 | 既存→拡張 | **妨害ノルマ**：自分に望ましい札がないとき、相手の必要な商品札をノルマとして確保する。その後完成/放棄できるかは別問題。金貨はノルマにできない。 |
| P03 | 拡張 | **金貨の競合制御**：複数の相手に使える金貨を、自分が必要なときに取る。相手の金貨依存度も見る。 |
| P04 | 拡張 | **相手の完成直前を妨げる**：次手番で相手が完成可能な札を優先して取る、または配り直す。相手の手番が自分より先か後かを区別する。 |
| P05 | 拡張 | **称号阻止**：相手に欠けた種類や最後の金貨を見積もり、その札を合法的に先取りする。O11 による「成立可能」と「狙っていそう」を分けて評価し、相手が称号を追っていなくても自然に成立する場合を見落とさない。単色や生粋では、相手が条件を維持しやすい札を残す影響も見る。ただし現在の場札を取っても同種の別札が後で出得るし、自分の得点機会を失う費用もある。 |
| P06 | 拡張 | **膠着を利用した時間制限**：相手が大きなノルマの完成を待つとき、パスや配り直しで残り機会を変える。配り直しは相手に有利な札を出す可能性もある。 |
| P07 | 拡張 | **多人数の標的選び**：誰を妨害するかを累計得点・そのラウンドの見込み・残りラウンド数・同点判定で切り替える。相手の手の確率も考慮する。 |
| P08 | 拡張 | **取り順による露出管理**：同じ手番に複数枚取れる場合、何を場に残すかを相手のノルマ/順番から選ぶ。順序は並び順ボーナスにも作用する。 |
| P09 | 拡張 | **商品札の永久除去**：相手の必要な商品札を自分のノルマにした後、後の自手番に放棄すれば捨て札となり、そのラウンドでは再出現しない。ただし相手も自分も利用できなくなり、手番も要する。 |
| P10 | 拡張 | **金貨の永久除去**：自分のノルマの収集札として金貨を取った後、完成前に放棄すれば捨て札にできる。金貨だけをノルマ札として取ることはできず、自分の未達成札も失う。 |
| P11 | 拡張 | **完成札の数字で相手の並び順を妨害**：自分も相手も同じ商品を収集でき、自分が残り1枚のとき、複数ある完成候補を比較する。自分の実績末尾・今回の収集末尾との同番号/連番ボーナスに加え、相手が各候補を取った場合の実績末尾・収集末尾との同番号/連番ボーナス、相手の完成可否を見積もる。相手に代替札があれば、その札まで考慮する。P01/P04の妨害を数字別に具体化した候補。 |
| P12 | 拡張 | **終盤の達成不能ノルマによる封鎖**：状態Aで有益なノルマがないとき、パスせず、相手の完成や同番号/連番に有用な商品札をあえてノルマにする。公開履歴から自分には達成不能と分かっていても選択可能（数字1は即達成なので対象外）。取得によってその札は場から消え、パスと異なり膠着カウンタもリセットされる。後で放棄すれば捨て札となるが、未達成のままラウンドが終われば自分の得点にはならない。相手の代替札、次手番までに補充される札、こちらの機会費用を別々に見る。P02/P09の妨害を「完成を意図しない終盤のパス代替」として明示した候補。 |

## 7. 終盤・複数ラウンド

| ID | 状態 | 戦術 |
|---|---|---|
| E01 | 拡張 | **山札切れまでの残り補充**：補充が必要な手番と残り山札枚数から、あと何回自分が行動できるか推定する。山札が0でも場が満杯なら、その時点で自動終了するとは限らない。 |
| E02 | 拡張 | **未達成を抱えない**：終盤は完成までの残り枚数・自手番の回数・同種の残量から、大きなノルマを取る危険を見積もる。 |
| E03 | 拡張 | **最後の収集順**：ラウンド末が近いとき、未来のつなぎよりも、今確定する並び順ボーナス・称号条件を重視する候補を作る。 |
| E04 | 拡張 | **追う/守るの分岐**：点差と残りラウンドから、確実な少点と低確率の高点を比較する。これは戦略側の重み変更にもなる。 |
| E05 | 拡張 | **タイブレークを意識**：累計得点が近い場合、達成回数と1回の最高点を区別して候補に反映する。まだ得点差があるときの優先度は別に決める。 |
| E06 | 拡張 | **リーダー交代・手番順**：次ラウンドの先手は1人ずれる。現在の終盤における手番順と、次ラウンドの先手を別々に扱う。カードの出現履歴そのものは次ラウンドへ持ち越さない。 |
| E07 | 拡張 | **逆転のための高分散候補**：現在の点差・残りラウンド・通常策の最終順位見込みから、確実な小点では勝ち目が薄い局面で13などの高得点ノルマ、達成ボーナスの段差、称号、ダブルを候補に加える。これは「必ず13を取る」という規則ではない。公開札から見た達成確率、完成に要る手番、失敗時の0点、成功してもなお逆転できない場合を含め、通常策と最終順位の見込みで比較する。切替の大枠は戦略側のトリガーとして扱う。 |

## 8. 更新の仕方

1. 各戦術の ID は固定する。候補の追加時は末尾に ID を足し、ルール変更で無効になったものは削除せず理由と版を記す。
2. 実装前に、その戦術が必要とする**公開観測**、推定方法、候補となる合法行動を決める。出現履歴は現在の場札だけでは復元できないため、公開イベントからCPUごとのラウンド内記憶を更新する。現在の `Game` オブジェクトをCPUへ丸ごと渡す場合も、山札の中身・順番、伏せた除外札、乱数状態へのアクセスは禁止する。
3. `既存→拡張` は近い動作が現行CPUにあるという意味で、確率モデルや優先順位まで同じとは限らない。評価結果や採用判断は別の文書・節で後から追加する。
4. Python と Unity/WebGL のCPU、公開状態の定義、ルール文書で同じ戦術・得点ルールを使う。戦略側でどの戦術をいつ選ぶかは、この台帳とは分けて設計する。
