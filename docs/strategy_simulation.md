# CPU戦略シミュレータ

戦術の差し込み試験に加え、優先順位を変更する**理由**を切り分けて比較するためのオフライン試験器。ゲーム中のCPU、Unity/WebGL、`cpu_ranking_v1.2.json` は変更しない。設計上の目的は [`cpu_strategy_design.md`](cpu_strategy_design.md)、戦術候補は [`cpu_tactics_catalog.md`](cpu_tactics_catalog.md) を参照。

```bash
python3 tools/strategy_simulator.py --deals 100 --players 3 --rounds 3 \
  --seed 42 --profile balanced --json-out /tmp/quota-strategy-3p.json
python3 tools/strategy_simulator.py --deals 100 --players 4 --rounds 4 \
  --seed 42 --profile comeback --json-out /tmp/quota-strategy-4p.json
```

`--rounds` は `1`、プレイヤー人数、人数の2倍などを指定する。省略時は人数分。`--deals` は独立した初期配りの数で、各配りについて全席を候補席にして対照CPUと比較する。各条件の試行数は `deals × players`。各条件は同じ初期シード、相手CPUキャラクター、候補席から開始する。行動が分岐した後の乱数消費や展開まで同じとは限らない。

## 4条件

- `fixed`：優先順位の切替なし。対照CPUと完全一致すべき検査条件。
- `macro`：点差、残りラウンド、リードを守る必要という大局的な根拠だけを使う。
- `tactical`：相手の完成直前、単色称号の脅威、場の13の見込み、自分の達成不能など、公開札からの戦術的な根拠だけを使う。
- `combined`：両方を使う。

現行の `StrategyPolicy` は小さな**試作方針**である。活動条件がない手は既存CPUに任せ、条件がある手では合法なノルマ候補を共通のスコアで比べ、残り1枚の収集候補、達成不能時の放棄を検討する。一部の局面では、既存CPUが提案しなくてもダブルや配り直しを宣言できる。ルールエンジンの合法性チェックを通し、山札の中身・伏せた除外札・乱数状態はポリシーに渡さない。

`--profile` は6種類：`balanced`、`efficient`（必要手番を重く見る）、`safe`（未達成を嫌う）、`comeback`（逆転の高得点候補を重く見る）、`denial`（相手への影響を重く見る）、`title`（称号の機会を重く見る）。いずれも同じ候補生成と判定条件を使い、仮の重みだけを変える。**強さの順位や適正な重みが確認されたわけではない。** 比較時は `--seed`、人数、ラウンド数、`--deals` をそろえる。

## 出力の読み方

`mean_score_delta`、`mean_win_share_delta`、`mean_margin_delta` は同じ初期条件の既存CPUからの差。正ならその指標では候補の方が高い。`*_95ci_by_deal` は席を1配りにまとめた近似的な95%信頼区間。配りが1つなら `null`。区間が0をまたぐとき、今回の試験だけで優劣を決めない。

`trigger_counts` は理由ごとに条件が成立した**意思決定回数**、`switches` は「理由が有る/無い」の状態が切り替わった回数、`changed` は既存CPUから実際に行動が変わった回数。`manual_specials` は方針から明示的に宣言した特殊行動の回数。`trials` には各初期条件と全4条件の結果・切替監査値が入る。`interaction` は `combined − macro − tactical + fixed` の配り単位の差で、2種類の理由を同時に使った効果の目安。対局が途中で分岐するため、単一局面の厳密な相互作用とは解釈しない。

称号狙いの推測は、現試作では主に単色の成立可能性と、代替候補があるとき同じ商品を選んだ履歴を使う。生粋・五種の意図、除外8枚を含む厳密なカード出現確率、相手の応答を考えた多手先読み、全ての戦術候補は未実装である。大きなノルマの達成見込みは公開情報に基づく保守的な**比較用代理値**で、真の達成確率ではない。結果が良くても、この試作品をそのまま本番CPUへ移植する根拠にはならない。

本格評価は異なるシード、3人/4人、ラウンド数、相手の型を分けて行う。とくにトリガーが少ない条件は全対局平均だけで判断せず、発動局面の行動・得点と誤推定例を確認する。将来、称号意図の推定器やカード出現モデルを改善するときは、4条件で**同じ推定器**を使い、切替規則の効果と推定器そのものの効果を別に測る。
