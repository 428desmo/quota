# CPU戦略の設計案（検討用）

2026-10-11 作成。これは戦術をどう使い分けるかの**提案**であり、実装済みの仕様や強さの評価結果ではない。現行CPUの正本は [`cpu_strategy_v1.0.md`](../cpu_strategy_v1.0.md)、具体的な候補は [`cpu_tactics_catalog.md`](cpu_tactics_catalog.md)、試験器は [`tactic_simulation.md`](tactic_simulation.md) を参照する。ボーナスのルール変更案は採用されていない前提とする。

## 戦略が決めること

戦術は「その場で何ができるか、どう見積もるか」、戦略は「何を得たいか、どの損失をどの程度避けるか、いつ方針を変えるか」と分ける。戦術IDを全順序に並べる方式は採らない。たとえば O01 は公開札の帳簿であって行動ではなく、C03（金貨を残す）と P04（相手の完成を防ぐ）は同じ札について競合し得る。両方を候補にして、共通の評価で比較する。

最終目的はゲーム終了時の順位と得点である。各ラウンドでの得点だけを最大化すると、最終ラウンドで負けを確実にする安全策を選び得る。逆に勝利確率だけを強くすると、根拠の薄い賭けを過大評価し得る。まず「予測最終得点・順位の見込み」を主指標とし、得点、勝利取り分、最高位相手との差、同点時の達成回数を並べて観察する。候補の採否はこの複数指標と実際の対局で判断する。内部評価の重みは実験前に仮置きし、固定の試験データだけに合わせ込まない。

## 局面の表現

方針を決める入力は公開情報と、それから推定した不確実性に限定する。

- **自分**：ノルマの種類・不足枚数、今の場で取れる枚数、実績の数字列・得点、達成回数、使用済みの配り直しとダブル、成立・失効した称号。
- **競争**：相手の公開ノルマと実績、各人の現在の得点と累計得点、順位と点差、手番順、相手が次手番に完成・称号達成する見込み。「称号が成立し得る」と「本人が狙っていそう」は別の推定値にする。標的は単に現在の首位とせず、最終順位への影響で選ぶ（O08・O09・O11・P07）。
- **時間**：山札と場札の枚数、膠着状態、自分へ残りそうな手番数、現在のラウンドと残りラウンド、次ラウンドの先手（O10・E01・E06）。山札0枚だけで即終了と決めつけない。
- **不確実性**：公開札の帳簿と配り直しの履歴を基に、未知の山札と伏せた8枚に整合する分布を作る（O01〜O07）。「絶対に出ない」と「まだ見ていない」を区別し、確率の信頼度も残す。配り直しで戻った札を除去札として扱わない。ラウンドが変われば札の履歴は初期化する。

## 行動選択の順序

1. **合法手と状態遷移を確定する。** ノルマ選択、収集、放棄、パス、特殊行動の宣言可能時点を守る。ダブルの2回目や、放棄後の同じ手番の再選択も別の局面として評価する。山札・除外札の実体は戦略に渡さない。
2. **戦術から候補を作る。** ノルマ選択は Q、収集と順序は C、放棄・パス・特殊行動は A、妨害は P、終盤は E の候補を作る。O と T の多くは候補を評価する特徴量であり、直接実行する行動ではない。少なくとも既存CPUの選択を常に候補に含める。
3. **同じ予測の上で候補を比べる。** 札の不確実な配置と相手の応答を、候補ごとに共通の条件で複数試行する。各候補について、完成までの見込み、未達成損失、並び順と達成ボーナス、称号の増分、相手の予測得点変化、残り手番、将来の権利価値を最終結果へ反映する。自分の得点や称号を個別に足した後、再び最終得点へ足して二重計上しない。
4. **実現可能性と機会費用を見る。** 称号が既に成立・失効した場合、その称号を追うためだけの加点は0。単色＋生粋は両立可能だが、現行ルールでは五種とそれらは両立しない（T07）。妨害札を取れば失う自分の得点や手番、ダブル・配り直しの消費、場に残す札の危険を差し引く。
5. **選択理由を記録する。** 候補ごとの主な増減と採用理由を機械的に記録し、同値に近ければ一定のルールで決める。再現可能なシードを使い、評価ノイズだけで手が変わり続けないようにする。

この順序は設計目標である。初期の実装は短い先読みや近似でもよいが、同一局面で比較する候補の前提・単位はそろえる。

### 特殊行動の温存

ダブルと配り直しには各ラウンド1回の使用機会がある。今使った場合の増分を、「今は使わず、後の難局で選べる価値」と比較する（A09・A13・A15）。将来価値は残り手番・必要札の不足・相手との競合・膠着危険から推定する。ラウンド終盤では未使用のまま失う確率が高まるため温存価値を下げる。ただし「山札が何枚以下なら必ず使う/使わない」という固定閾値だけにはしない。ダブルの途中で山札が尽きると2回目を実行できない場合も考慮する（A12）。

### 妨害を採る条件

妨害は相手の得点を下げるだけでは足りず、自分の**最終順位を改善する見込み**で測る。自分があと1枚で完成し、同種を争う相手もいるときは、自分の数字ボーナスと相手の完成・数字ボーナスの減少を同時に比較する（P11）。終盤に有望なノルマが無いときは、達成不能と公開情報から確定できる妨害ノルマ（P12）もパスと比べる。ただしそれで自分の手番・特殊行動・称号が犠牲になる点を含む。標的は先に行動する相手と、最終順位を争う相手を優先して検討する。

## 方針をどう切り替えるか

現行CPUは「切替前の取り方 → 条件成立 → 切替後の取り方」という一方向の構造で、切替後は戻らない。分かりやすい一方、同じゲームの次ラウンドで状況が逆転しても元へ戻れず、札の選び方以外の判断には効果が届きにくい。新案では**毎回の意思決定で方針を再計算**し、次の状況を区別する。

- **通常・柔軟**：完成可能性と期待得点を優先し、称号は無理なく付随する分だけ狙う。特殊行動をすぐ使う利益が低ければ保持する（Q04〜Q08・A15・T05）。
- **守る**：ゲームの残りラウンドと点差から優位が見込め、失敗すると順位が下がる場合。大ノルマや未達成を抱える危険を強く抑える。小さく確実な得点や相手の逆転手段の阻止を検討する（E02・E04・P07）。
- **追う**：残りラウンドが少なく、通常の得点経路では順位改善が難しい場合。成功確率だけで高得点候補を切り捨てず、13のノルマなども含め、実際の逆転に必要な幅と失敗時の差を比較する。称号や達成ボーナスの段差も、成立見込みと一緒に評価する（Q03・Q09・T01〜T06・E04・E07）。
- **競合への応答**：相手が同種・金貨を欲し、次の手番で完成しそうな場合。必要札の先取り、収集順、配り直しを比較する。これは一時的な重み変更であり、その相手が放棄・達成したら解除する（P01・P04・P11）。
- **ラウンド終盤の救済**：山札・手番・膠着から、現在のノルマが完成困難になった場合。放棄、特殊行動、確実な小ノルマ、パス、妨害ノルマを候補にする。ここで未使用権利の将来価値は急速に下がる（A01〜A03・A15・P12・E01〜E03）。

これらは相互排他的な「人格」ではない。たとえば「追う」局面で同時に「競合への応答」が必要になる。まず状況ごとに評価の重点を調整し、絶対条件で切替を固定しない。一方、僅かな点差変動や確率推定の揺れで方針が毎手番反転するなら、切替閾値に幅を持たせる、同点程度の候補では前手番の方針を保つ、といった安定化を入れる。達成不能確定などの強い情報には即応する。

### 優先順位を変える理由を分けて評価する

現案には両方の種類の理由が含まれるが、どちらが効いたかを記録する仕様は明確でなかった。次の2軸として明示する。

- **戦術的な根拠**：同じ種類を争う相手の完成が目前、相手が称号を狙う可能性が高い、公開札から13を完成できる見込みが上がった、現在のノルマが達成不能と判明した、配り直しで欲しい札が戻り得る、など。特定の戦術・観測IDと推定値を伴う。
- **戦術に依存しない大局的な理由**：累計点差、残りラウンド数、今の順位で守るべきか追うべきか、キャラクターのリスク許容度、など。具体的な札の好機がなくても、最終順位を狙うために評価の重みを変える理由になる。

たとえば「点差が開いた」は大局的な逆転トリガーであり、「13が公開札から達成できそう」は戦術的な根拠である。前者だけなら13を機械的に選ばず、高分散候補を比較対象に加える。後者だけなら通常の期待得点評価でも13が候補になり得る。両方そろった場合も、失敗時の損失と成功後の最終順位を見て選ぶ。相手の称号についても、成立可能性だけで阻止策を採らず、相手が狙う可能性・自然成立の見込み・自分の機会費用を分ける。

評価時は、(a) 優先順位を固定、(b) 大局的な理由だけで切替、(c) 戦術的な根拠だけで切替、(d) 両方で切替、の4条件を**同じ候補生成・同じ推定器**で比較する。切替の発生回数、理由ID、前後の候補順位、実際に行動が変わった回数、逆転率、平均得点と未達成率を記録する。点差や称号狙いの推定が間違った局面も別に見て、単に切替回数が多い方を高評価にしない。これで「戦術の改善」と「切替規則の改善」を混同しにくくする。

## 比較する戦略候補

最初から数千通りの重みを組み合わせず、解釈できる少数の候補を試す。以下は評価対象の案であり、強弱の予断ではない。

1. **現行CPU**：対照。既存のキャラクターとランキングの動きを保存する。
2. **得点効率型**：完成確率、獲得得点、必要手番の比を重視。特殊行動・妨害・称号の判断は控えめ。
3. **堅実型**：未達成と権利の空振りを重く見て、終盤は確定得点を選びやすくする。
4. **逆転型**：残りラウンドと予測点差に応じ、高得点ノルマ・称号・ダブルの価値を変える。点差が小さいときまで賭けない。
5. **競合対応型**：相手の完成・並び順・称号を妨げる効果を高める。自分の明確な得点機会は捨てすぎない。
6. **称号機会主義型**：自然に成立しそうな称号だけを積極的に追い、成立困難・排他が判明したらすぐ通常評価へ戻す。

各型の差はルールの例外ではなく、同じ候補生成と予測を使った**重み・リスク許容度・先読みの長さ**に限定する。戦略の個性は固定しつつ、上記の局面に応じた調整は全員に共通で適用する案から始める。なお現在の5184キャラクターのID・名前・順位は旧仕様に結び付いており、この6案を既存IDの別名として流用しない。

## 試験と採用の進め方

1. まず観測・候補生成の正確さを検証する。伏せた8枚や実際の山札順序を見ていないか、配り直し後の札を消失扱いしていないか、収集順・特殊行動・放棄後の合法性が保たれるかを確認する。
2. 現行CPUを固定の対照とし、少数の戦略候補を同じ初期シード・キャラクター・席で比較する。現行の [`tools/tactic_simulator.py`](../tools/tactic_simulator.py) は公開観測と差し替えポリシーを使えるが、基本は既存CPUの行動への介入であり、特殊行動の**宣言を新たに提案**する完全な戦略実装にはインターフェース拡張が必要である。
3. 3人/4人、1ラウンド/人数分/人数分×2、相手の型の組合せ、席順を分けて測る。平均得点だけでなく、勝利取り分、最高位相手との差、称号成立・未達成・特殊行動の未使用率、妨害の発動回数を記録する。上の4条件で優先順位変更の理由も分離する。発動が少ない手法は対局全体の平均差だけで判断しない。
4. 同じ配りを対照/候補で共有する比較、別シードでの再試験、戦術の除去試験を行う。戦略同士を戦わせ、現行CPU相手だけに通じる選択を避ける。ルール変更案を評価するときは、**同じ戦略を新旧両ルールで試す**条件と、**各ルールで戦略を再調整する**条件を分ける。
5. 改善が確認されてから Python と Unity/WebGL の判断をそろえる。公開情報、乱数、同点処理、音やアニメーションに依存しない判断を同じ条件で検証する。ゲームルールやCPU方針が変われば旧ランキングと試合数を混ぜず、新しい版で計測し直す。

当面の実装順は、①公開情報の帳簿と不足確率、②候補ごとの完成見込みと得点、③特殊行動の比較、④相手への影響と順位、⑤戦略ごとの局面適応、が妥当。最初の二つが誤ると後段の高度な戦略も誤った見積りを増幅する。戦術カタログの候補を一度に全部採用する必要はない。
