# ボーナス変更案のシミュレーション

2026-10-11。新しい試験用CPU 6人を対戦させ、現行のボーナスと変更案を比較した。**ゲーム本体の得点ルールは変更していない。** 実装は [`bonus_rules.py`](../tools/bonus_rules.py) と [`bonus_rule_simulator.py`](../tools/bonus_rule_simulator.py)。機械可読な結果は [`3人戦`](bonus_rule_results_3p.json)・[`4人戦`](bonus_rule_results_4p.json) に保存した。

## 比べた案

現行は「五種の品揃え」が4種類の商品と金貨を各1枚以上で＋5点、達成ボーナスは7枚から始まる。変更案は以下の通り。

- 五種の得点だけを＋3点に下げる。
- 五種の成立条件を各種類・金貨2枚以上、または3枚以上にする。
- 五種類を含み、実績の合計を8枚・10枚・15枚・20枚以上にする。これは検討中に加えた中間案。
- 達成ボーナス＋1点の開始を6枚、または5枚に下げる。7〜9枚の＋1、10〜12枚の＋3、13枚の＋6は据え置く。
- 各種類2枚以上と、達成ボーナス6枚開始を組み合わせる。

## 方法

6人から、3人戦は全20組、4人戦は全15組を作った。各組で8つの初期配りを用い、各プレイヤーを全席に回した。**各案・各人数480対局**。それぞれ3ラウンド、4ラウンドの対局で、同じ組・シード・席順を各ルールで再試行した。各キャラクターの試行数は3人戦240対局、4人戦320対局。CPUは採点上の達成ボーナスと各種類の必要枚数を読み、候補の評価に使う。一方、合計実績枚数の境界を明示的に狙う専用戦術や、称号の成立確率・相手の称号狙いを厳密に推定する戦術はない。得点・行動・勝率は変更案のルールで最初から対戦させた結果で、同じ対局履歴の単純な採点し直しではない。

## 結果と読み方

現行ルールでは、「五種の品揃え」の成立は**100人・ラウンドあたり3人戦12.71回、4人戦5.27回**。各種類2枚を条件にすると**4.33回／1.05回**、3枚なら**1.02回／0.07回**まで落ちる。3枚条件は、とくに4人戦では称号を実質的に消す。＋3点案は称号の出現頻度をほぼ変えないので、「ノルマ1や金貨で簡単に達成できる」という印象への対処にはならず、成立したときの重みを下げる案となる。

現行の＋5点による平均加点は、成立回数から計算すると**3人戦の1対局あたり約1.91点、4人戦で約1.05点**。平均最終得点約128点に比べると小さい。＋3点案で平均最終得点は3人戦で128.61→128.47点、4人戦で127.38→126.98点だった。称号の頻度や順位を変えるより、加点幅の調整として働く。

達成ボーナスを6枚から付けると平均最終得点は3人戦で**128.61→128.95点**、4人戦で**127.38→128.47点**。5枚からなら**130.90点／129.23点**。開始を下げるほど点は増えるが、五種の出現頻度はほとんど動かない。ノルマ選択の平均数字も大きくは変わらなかった。したがって、達成ボーナスの開始枚数は五種の「簡単さ」を直接直す手段ではなく、短いノルマの相対価値を調整する別のつまみと考えるのが適切。

各キャラクターの**1位取り分の変化は、多くの条件で数パーセントポイント以内**。配りを対応させた95%近似区間は、多くが0をまたぐ。強弱の序列が安定して変わったとはまだ判断できない。得点差には新しい得点の直接効果と、CPUの手の変化の双方が入る。多数の案とキャラクターを探索しているため、個別の区間が0を外れても確証と扱わない。

五種の成立のしやすさを直接抑えたいなら、**実績合計枚数の条件**も候補になる。ただし、今回のCPU対局では五種類が揃った時点ですでに10枚以上の実績があり、8枚・10枚条件は現行ルールと結果が完全に同じだった。15枚でも3人戦は12.71回のまま、4人戦は5.23回。20枚にして初めて12.55回／4.60回になり、効果は小さい。一方、各種類2枚条件は4.33回／1.05回と大きく減らす。**現在の6人は小さいノルマを使った五種の早期達成を意図的には狙わない**ため、総枚数条件の無効さを人間相手にも一般化しない。実際に採用する前には、その手筋に特化した相手との試験と、表示・説明のわかりやすさを確認する。今回の試験だけでルールは確定しない。
